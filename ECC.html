What it is

The Cross-Asset Mitigation Graph is an interactive 3D force-directed network that maps every significant asset in a plant portfolio as a node, connects assets that can trigger each other's failures with cascade links, and lets analysts add, toggle, and price mitigation strategies — all while watching the portfolio-level TVaR and EAL update in real time.

It implements the ECC (Endogenous Crisis Correlation) concept from the iARM™ framework: failures do not occur independently. A single trigger event — a heater trip, a power interruption, a steam loss — can cascade to multiple downstream assets, amplifying both expected loss and tail risk beyond what any single-asset model would predict.

Core question answered

Which mitigation investment, applied where, removes the most tail risk per dollar — accounting for the fact that one asset's failure can cascade to several others?

Asset nodes

Each node represents a plant asset or system. Color encodes risk tier; size encodes relative tail importance.

Node tiers
High tail contributor
Top-ranked assets. Radius grows with tailPct contribution. Typically >10% of portfolio tail.
Medium tail contributor
Ranked assets with moderate exposure (<1% of tail), still material to overall loss.
Low / isolated
Minimal tail contribution, no significant cascade connections. Manage cost not risk.
Trigger node
Unranked by own exposure, but causes cascade failures across multiple downstream assets.
Mitigated
Any node with at least one active strategy applied. Stroke and fill turn green.
Node sizing formula
trigger: r = 28 px (fixed — large to convey structural importance)
high: r = 22 + tailPct × 0.18
med: r = 18
low: r = 14

All radii are further scaled by the perspective factor during 3D projection, so nearer nodes appear larger.

Why shared dependencies matter

DCU Coke Drums has two trigger parents (DCU Heater and Steam Gen). A Steam Gen failure simultaneously impairs two of the top-three tail contributors — making Steam Gen the highest-leverage mitigation target even though its own EAL is only $210K.

3D physics engine

A custom 3D force-directed simulation runs entirely in JavaScript. There is no WebGL — the scene is a single SVG element and nodes are translated SVG groups. The 3D effect comes from perspective projection of a live force simulation in x/y/z world coordinates.

Force components
1
RepulsionEvery pair of nodes repels at force ∝ 9000 / distance². O(n²) — acceptable at 13 nodes.
2
Spring attractionEach cascade link is a spring: stiffness 0.04, rest length 150 units. Trigger–dependent pairs cluster together.
3
Center gravityWeak center pull (0.02) prevents nodes drifting off-screen. Scales with alpha so it weakens as the simulation cools.
4
Damping + bounding sphereVelocities ×0.88 each frame. Positions clamped to world sphere radius 340 units.
5
Alpha coolingAlpha starts at 1.0 and decays ×0.97/frame. All forces are multiplied by alpha, so the layout settles over ~200 frames. Reheats to 0.3 on drag or Reset View.
Perspective projection
rx = x·cos(yaw) + z·sin(yaw) yaw rotation
ry = y·cos(pitch) − rz1·sin(pitch) pitch rotation
rz = y·sin(pitch) + rz1·cos(pitch)

persp = FOCAL / max(FOCAL + rz, 80) FOCAL = 1100
sx = centerX + panX + rx · persp · zoom
sy = centerY + panY + ry · persp · zoom

The same perspective factor controls node radius, stroke width, link width, and depth-based opacity (0.38–1.0). Depth sorting re-appends SVG elements far→near every frame so closer nodes always render on top.

Seeded layout

Node positions are initialized with a Mulberry32 seeded PRNG (seed = 42), ensuring the starting layout is identical every page load — so demos always begin from the same state. Dragging a node pins it, persisting its position across spin cycles. Double-click to unpin.

Mitigation strategies

Clicking any node opens the Mitigation Strategies panel. Each node can carry any number of discrete strategies, each with its own frequency reduction, severity reduction, annual spend, and on/off toggle.

Strategy fields
FieldWhat it meansHow it's used
OnToggle to include or exclude this strategyOnly "on" rows contribute to the results bar and ROI preview
NameFree-text label (e.g. "Vibration monitoring")Displayed in tooltip; no numeric effect
Freq↓%Percent reduction in event frequency (λ)Applied multiplicatively with other active strategies
Sev↓%Percent reduction in per-event costApplied multiplicatively with other active strategies
$/yrAnnualized cost of this strategySummed across enabled strategies; used in ROI calculation
Multiplicative reduction model
freqFactor = ∏ (1 − freq_i / 100) for each enabled strategy i
sevFactor = ∏ (1 − sev_i / 100)

freqRed% = (1 − freqFactor) × 100
totalCost = ∑ cost_i

Two strategies each claiming 30% frequency reduction combine to 1 − (0.7 × 0.7) = 51% combined, not 60%. This reflects the physical reality that each strategy operates on the residual risk left by the previous one.

Trigger node leverage

When strategies are applied to a trigger node, its cascade links turn green. This signals that the mitigation is not just reducing that node's own EAL — it is also reducing the induced failure rate in every dependent asset downstream.

ROI calculation

The panel's ROI preview and the portfolio summary bar use the same logic, applied at asset level and portfolio level respectively.

Per-node ROI
ealRed = EAL × [1 − (1 − freqRed/100) × (1 − sevRed/100)]
tvarRed = TVaR × [1 − (1 − freqRed/100) × (1 − sevRed/100)]

Tail ROI = tvarRed / totalAnnualCost

A TVaR Tail ROI of 2.5× means that for every dollar spent annually, $2.50 in tail exposure is eliminated.

Portfolio summary
Total Spend = ∑ cost_i (all enabled strategies, all nodes)
TVaR Reduction = ∑ [node.tvar × combinedFactor_node]
Portfolio Tail ROI = TVaR Reduction / Total Spend
Decision use

The Portfolio Tail ROI figure translates a reliability engineering decision into financial language: “We propose spending $X per year, and our model projects that removes $Y from the tail risk reserve requirement — a Z× return on that spend.”

Current limitation

This ROI model does not yet propagate cascade effects. A strategy on a trigger node reduces only that node's own EAL/TVaR in the calculation, not the induced risk in dependent assets. Full cascade-adjusted ROI requires a Monte Carlo propagation pass — a planned enhancement.

Controls
  • Left-drag background — trackball rotate
  • Scroll — cursor-centered zoom (0.2×–4.0×)
  • Middle-drag — pan the scene
  • Left-drag node — move & pin node
  • Double-click node — unpin (returns to physics)
  • Click node — open Strategies panel
  • Hover node — tooltip with EAL, TVaR, cascade links
  • Auto-Spin ON/OFF — continuous slow yaw rotation
  • Reset View — home camera, reheat physics
  • Apply Mitigation — commit strategies, update node color & bar
  • Clear All — remove all strategies from active node
  • + Add Strategy — append blank row to strategy table

Dragging a node marks it pinned and excludes it from physics. Double-clicking unpins and returns it to the simulation. A plain click (no drag movement) does not pin — the panel opens and the node stays free.

Why it matters
1
Structural leverage of trigger nodesThe DCU Heater's own EAL is $320K — far below the top-ranked assets. But it is the direct cause of failures in DCU Coke Storage/Loadout (#1, $3.2M EAL) and DCU Coke Drums (#2, $1.8M EAL). A $50K/yr inspection upgrade potentially removes exposure across all three simultaneously.
2
Shared dependencies amplify single-point exposureSteam Gen triggers both DCU Coke Drums and CDU Atm Gas Oil Pumps (#2 and #3). A single Steam Gen failure creates correlated losses in two top-tier assets in the same operational period — exactly the tail event that makes TVaR diverge from EAL. The graph makes this coupling visible; a ranked list does not.
3
ROI comparison across the portfolioBy entering strategy costs and reductions for multiple nodes and watching the Portfolio Tail ROI update, an analyst can compare "spend $80K/yr on vibration monitoring for AGOP pumps" against "spend $60K/yr on heater online inspection" and present the result in financial terms that a CFO can act on.
iARM™ framework alignment

This graph implements the cross-asset dimension of the iARM™ mission: quantify cost risk, prioritize mitigation efforts, and communicate outcomes in language that drives decisions. The 3D layout spatially separates asset clusters by cascade relationship, making structural dependencies legible in a way that a table or ranked list cannot.
